Core algorithm (language-agnostic)

Simple browser implementation (Canvas)

<script>

const ctx = canvas.getContext("2d");
const upload = document.getElementById("upload");

upload.onchange = e => {
  const img = new Image();
  img.onload = () => {
    canvas.width = img.width;
    canvas.height = img.height;
    ctx.drawImage(img, 0, 0);
  };
  img.src = URL.createObjectURL(e.target.files[0]);

document.getElementById("invert").onclick = () => {
  const imageData = ctx.getImageData(0, 0, canvas.width, canvas.height);
  const data = imageData.data;

  for (let i = 0; i < data.length; i += 4) {
    data[i]   = 255 - data[i];     // R
    data[i+1] = 255 - data[i+1];   // G
    data[i+2] = 255 - data[i+2];   // B
    // data[i+3] is alpha, unchanged
  }

  ctx.putImageData(imageData, 0, 0);
};
</script>

color inversion → color spaces → linear algebra

image filters → convolution → Fourier transforms

text analysis → probability → information theory

audio tools → signals → transforms

You don’t have to announce the math.
The math arrives because the tool demands it.

A clean philosophy you can adopt (implicitly)
You don’t need to state this on the blog, but it can guide your choices:

“I build small, self-contained tools that perform a single transformation on data. Each tool is correct, explainable, and useful.”

That’s it. That’s a career-long throughline.

How this changes your blog tone (important)
Your posts can now be:

shorter

factual

reproducible

calm

technical

Instead of:

“Here’s what this means to me…”

You write:

“Here’s what the tool does. Here’s how it works. Here’s why it’s correct.”

That alone will make the blog feel like it changed overnight — in a good way.

Your first post can be extremely modest
Something like:

Image Color Inverter (Client-Side Web App)
This app loads an image into memory, iterates over its pixel buffer, and replaces each RGB channel value with its complement. The transformation is linear, reversible, and runs in O(n) time where n is the number of pixels.

That’s enough. No apologies. No overreach.

reducing impostor syndrome

building a portfolio that ages well

creating things you can refactor and extend later
